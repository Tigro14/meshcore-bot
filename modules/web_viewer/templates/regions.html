Fonctionnalités Régions

Page complète
Contexte. Un client MeshCore sans région configurée diffuse chaque message en FLOOD global, rebroadcasté par tous les répetiteurs du maillage. Avec une région (TC_FLOOD), le message ne traverse que les répetiteurs détenant la clé de région. Ces fonctionnalités aident à mesurer et corriger le trafic non-scopé.
Region Warnings Settings → Region Warnings

Surveille chaque message de canal et le classe en scoped, global (sans région) ou unknown, par canal et par jour.

  • Comptage (par défaut, gratuit) : tallies stockés dans region_scope_daily, rien n'est transmis.
  • Alertes aux émetteurs (off par défaut, dry-run d'abord) : DM ou réponse en canal aux émetteurs dont les messages sont confirmés sans région. Limites : cooldown par émetteur, plafond journalier, délai mesh.
  • Un émetteur sans Name: ne peut jamais recevoir d'alerte ; la livraison DM exige un contact connu.

Config : section [Region_Warnings] dans config.ini ou via la page web. Sauvegarde = hot reload, pas de restart.

Flood Scopes (réponses scopées) Radio → Region Scopes

[Channels] flood_scopes définit les régions auxquelles le bot répond. Un message non-scopé n'obtient pas de réponse command si l'allowlist ne contient pas *.

  • Les flood_scope.<region> par région et outgoing_flood_scope_override sont éditables depuis la page Radio (card Region Scopes).
  • Le Default Region Scope de la radio (réglage firmware NodePrefs.default_scope_name) peut aussi se définir depuis la même page.
  • Le bot ne répond qu'aux messages dont le scope correspond ; les messages globaux sont ignorés si * n'est pas listé.

Lien avec Region Warnings : les warnings observent avant l'allowlist, donc ils voient le trafic que flood_scopes filtre — c'est exactement le trafic non-scopé qu'ils doivent mesurer.

Scopes par canal config.ini

flood_scope.<canal> = #région dans [Channels] permet de restreindre les réponses du bot à un scope par canal. Affiché en lecture seule sur la page Radio.

Stockage & rétention
  • region_scope_daily : une ligne par canal par jour (scoped / global / unknown).
  • region_warning_events : une ligne par décision d'alerte qui a atteint l'étape d'envoi (envoyée, échouée, ou retenue en dry-run).
  • Rétention pilotée par [Data_Retention] region_warning_retention_days (défaut 90 j).
